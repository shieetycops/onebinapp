# Jembatan Rilis (working name): build spec

Static catalog of GitHub desktop apps (later: AI tools) with one-click download to the visitor's OS. No server, no DB. Everything below is a contract between the Python builder and the Next.js site. Change it here first.

## 0. Ground rules
- Repo root: E:\githubfordummies. Builder: `scripts/catalog/`. Site: `site/` (Next.js, `output: 'export'`). Generated data: `site/public/data/`. Raw cache: `data/catalog_cache/` (never published). History: `data/history/snapshot-YYYY-MM-DD.json`.
- The picker is `scripts/picker_v3.py` + `scripts/classifier_v3.py`, UNCHANGED. The builder verifies their sha256 against `data/round3/hashes.txt` at startup and refuses to run on mismatch. Do not edit these files, `LOCK.md`, `hashes.txt`, or anything under `data/round3/`.
- The picker has been evaluated only for windows/macos/linux strict extensions (.exe .msi .msix .appx(+bundle) .dmg .pkg .AppImage). Round 3 closed with windows and macOS COVERAGE below target (picker is often silent) and macOS sample check open. So: the "picker silent -> show asset list with OS labels, user chooses" path is COMMON, not an edge case. Android `.apk` uses a separate name-only rule written in the builder header and labelled as unevaluated in the trust label.
- The GitHub token is in `~/.gh_token`. It must never appear in any output, log, cache file or committed file.
- Never write the word "aman" (safe) about any app or AI tool. Trust labels say what was checked, nothing more.
- Heavy jobs one at a time (the machine has killed a process for low memory): never run `next build` and Playwright and a fetch concurrently.
- Slugs are lowercase `owner--repo` (NTFS is case-insensitive). Dedupe repos by GitHub `databaseId` (renames).

## 1. Builder (`scripts/catalog/build_catalog.py`, modules beside it)
Inputs (candidate repo names, union, case-insensitive, deduped by databaseId after fetch):
- `data/round3/seen_repos.txt` (1148), round-3 drawn repos (`data/round3/pool_info.json` order[:300]), unique `fullName` in `data/ext/komi/komi-store-backend-data/cached-data/**.json` (komi), plus `data/catalog_extra.txt` if present (one repo per line; trending additions land here).
Curation = round-3 rules C1-C4b EXACTLY, moved from `scripts/18_draw_round3.py` into `scripts/catalog/curation.py` (that script runs the draw on import; do not import it). Gate: the new module must reproduce `data/round3/curation_decisions.json` (300/300 `curated` flags) from the cached round-3 `data/round3/raw/*.meta.json`; the builder test asserts it. Also apply the manual deny lists `data/curation.json` ("denied") and `data/curation_extra_deny.json`.
Fetch: GraphQL, aliased batches (start at 25 repos/query; measure `rateLimit{cost remaining}` and print the real cost), fields: databaseId, nameWithOwner, description, stargazerCount, forkCount, isFork, isArchived, isDisabled, owner{login avatarUrl}, repositoryTopics(first:20), licenseInfo{spdxId}, homepageUrl, pushedAt, latestRelease{...}, releases(first:15){ tagName name isPrerelease isDraft publishedAt descriptionHTML? NO: use `description` markdown, url, releaseAssets(first:100){nodes{name size downloadCount downloadUrl updatedAt}} }. Cache raw responses per repo under `data/catalog_cache/` with fetched_at; `--max-age-hours` (default 20) reuses cache; `--limit N` and `--only owner/repo` for tests. Respect rate limit (sleep until reset when remaining < 200). Resumable: a crashed run continues from cache. Output is written atomically (temp file + rename).
Inclusion rule: curated AND >=1 release (non-draft) having >=1 installer asset for >=1 OS, where installer = round-3 strict extensions plus `.apk` (Android). No requirement of OS completeness. Report how many curated repos drop out for lack of an installer.
Picker use, per release (latest stable, latest pre-release, and up to 15 releases): for each cell in {windows x64, windows arm64, macos arm64, macos x64, linux x64, linux arm64} call `picker_v3.pick(names, os, arch)`. Store pick (asset name or null). Also store `assets[]` with a per-asset `os` guess from `classifier_v3.classify` (os, arch, type) for the labelled asset list (guess is a label for the user, not a verdict).
Outputs (`site/public/data/`):
- `catalog.json`: `{generated_at, picker_sha256, count, apps:[card...]}`. Card (small!): `slug, repo, name, owner, avatar, desc (<=160 chars), stars, platforms:["windows","macos","linux","android"] (only OSes with an installer in latest stable or pre-release), category (one of the ids in section 3), dev (bool), latest_release_at, is_new (published within 14 days), version, trust:{...} , trending:{d7,d30,rank|null}`.
- `apps/<slug>.json`: card + `homepage, license, topics, forks, downloads_total, releases:[{tag,name,prerelease,published_at,notes_md (truncate 4000 chars),assets:[{name,size,downloads,url,os,arch,kind}], picks:{"windows-x64":name|null,...}}]`.
- `stats.json`: counts per platform, per category, `dropped:{no_installer:n, failed_curation:n,...}`, `uncategorized:n`, `dev_category:n`, `picker_silent_share` per cell.
- Platform = OSes available; app with only Linux still shows with only the Linux badge.
History: each build writes `data/history/snapshot-YYYY-MM-DD.json` `{repo: {stars, downloads}}` (overwrite same day). Trending (`trending.json`) = star delta over 7 and 30 days from the oldest snapshot within window; until 7 days of history exist, `trending.ready=false` and the site sorts by latest release.
Scheduling: the builder is one command (`python -I scripts/catalog/build_catalog.py`), idempotent, safe to run from cron/GitHub Actions; write `docs/REBUILD.md` with a sample workflow file (do not enable it).

## 2. Trust labels (read `report/index.html` for the earlier design and reuse its wording where it exists)
Per app, only facts the builder checked: `curated_rules` (C1-C4b passed), `has_checksum_asset` (a .sha256/.sig/.minisig sidecar exists in the release), `signed_hint` NOT claimed (we do not verify signatures), `source: GitHub release, direct link`, `picker: picked by name only (evaluated on 300+ repos, not a safety check)`. Never "aman". SmartScreen (Windows) and Gatekeeper (macOS) guide pages explain the warnings; the app page links to the one for the visitor's OS.

## 3. Categories (ids; Indonesian labels in site i18n)
`media, produktivitas, ai, privasi, jaringan, sosial, baca, alat, game, developer`. Map by GitHub topics (table in `scripts/catalog/categories.py`, keyword lists per category, first match by priority; ties resolved by that order). Apps with no mapped topic -> `alat` if desktop-generic else `lainnya` is NOT allowed: use `alat` and count them in `stats.uncategorized`. `developer` = topics like cli, devtools, developer-tools, git-client, ide, terminal, api-client, database-client...; it is hidden from the default view (filter chip "Untuk developer" turns it on). Tension to report: C4a/C4b already drop libraries and CLIs, so `developer` will be small; do not weaken curation to fill it.

## 4. Site (Next.js, static export; `site/`)
- Pages: `/` (home), `/app/[slug]`, `/tentang` (about, sources, attribution, trending sources), `/panduan/windows` and `/panduan/macos` (SmartScreen / Gatekeeper), `/saya` ("App saya", localStorage list), later `/ai`, `/ai/[slug]`.
- Language: Indonesian default, English option. Next `i18n` config does not work with `output: 'export'`: use a `[lang]` path segment OR a client dictionary with a persistent toggle; whichever, `/` must work without server logic. Dictionaries in `site/src/i18n/{id,en}.ts`.
- Home: cards (icon=avatar, name, owner, description, OS badges for available OSes only, stars, last release time, "rilis baru" badge), search (client-side over catalog.json), platform filter, category filter, sort: popular / latest (/ trending when ready). Default view hides `dev`. Paginate or virtualize: catalog may hold thousands of apps.
- App page: detect visitor OS from `navigator.userAgentData` then `userAgent`. Big button "Download untuk [OS]" linking straight to the GitHub release asset URL, ONLY when the picker picked something for that cell. macOS: the UA cannot tell Apple Silicon from Intel; if arm64 and x64 picks are the same asset show one button, otherwise two labelled buttons, never guess. If the picker is silent or there is no build for the visitor's OS, show the asset list with OS labels (and say plainly "belum ada build untuk OS Anda" when so) and let the user choose. Version selector, tabs stable / pre-release, asset list, stats (stars, downloads, forks, license), release notes rendered as markdown WITHOUT raw HTML (untrusted). Trust label block and the SmartScreen/Gatekeeper link. "Tambah ke App saya" button.
- "App saya": localStorage (wrapped in try/catch; page works without it).
- Footer: attribution to Komi Store (Apache-2.0, github.com/komi-store/komi-store and its backend-data repo) for the repo list, GitHub for data, round-3 caveats link. Check the LICENSE of the komi backend data before republishing names; record the finding in `/tentang`.
- Visual identity: own, NOT resembling Komi Store (distinct palette, type, layout). Mobile first, works at 360 px. Light/dark.
- `site/package.json` scripts: `dev`, `build` (next build => `out/`), `serve` (static server on out/, port 4173), `test` (Playwright).

## 5. Tests (Playwright, against the built `out/` served statically, never the dev server)
Run one at a time. Fixtures live in `site/tests/fixtures/` (own small `data/` tree selected by a build env var, e.g. `DATA_DIR`) covering: exact pick; picker silent -> asset list; mac release with separate arm64/x64 assets -> two buttons; APK-only app; no build for the visitor's OS. User agents: Windows, macOS, Linux, Android. First test asserts Playwright's `userAgent` override also changes `navigator.userAgentData` (if it does not, stub with `addInitScript`, otherwise macOS/Linux/Android runs silently detect Windows). Also: phone viewport 360x740, "App saya" survives reload, language toggle, search, platform filter, default view hides developer apps, no raw HTML from release notes.

## 6. Reporting (after build)
App count per platform and per category, dropped counts with reasons, uncategorized count, dev count, picker-silent share per cell, cost of the fetch (GraphQL points).

## 7. Later parts (do NOT start before part 1 builds and its tests pass)
B: "Untuk AI tools" (`catalog-ai.json`); C: trending additions. Their briefs are separate files (`site/SPEC_AI.md`, `site/SPEC_TRENDING.md`), written when started.
