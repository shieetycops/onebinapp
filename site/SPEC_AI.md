# "Untuk AI tools": spec (part B). Read SPEC.md first; its ground rules apply here too.

Sources of truth: `site/research/install_methods.md` (install mechanisms, official URLs) and `site/research/registry_trending.md` (registry API, trending terms). A button exists ONLY where install_methods.md gives an official URL for that (tool x type) cell; each install method in the data carries `source_url`. Anything not in that file = no button (show "belum ada cara pasang terdokumentasi untuk tool ini"). Never write "aman"/"safe" anywhere. Do not edit scripts/picker_v3.py, classifier_v3.py, data/round3/*.

## 1. Inclusion pipeline (`scripts/catalog/build_ai.py` + modules; stdlib only; python -I)
Candidates, each entry records every source it came from in `sources:[...]`:
- `registry`: official MCP registry `GET https://registry.modelcontextprotocol.io/v0.1/servers` (cursor pagination, `limit=100`, only `isLatest`/status active, retry with backoff, at most one full crawl per run, cache under `data/catalog_cache_ai/`; per docs, not more than ~hourly). Map each server's `repository.url` to a GitHub repo; keep the server.json from the registry as the MCP manifest.
- `gh_topic`: GitHub search `topic:T stars:>=20` for T in {mcp-server, mcp, claude-skills, agent-skills, claude-code-plugin, claude-code-plugins, claude-code-skills}, sorted by stars, pages up to 5x100 per topic (cache raw).
Rank all candidates by stars; process in descending order until 200 entries pass curation (hard cap: 1500 repos examined). Target: 100-200 entries.
Fetch via GraphQL aliased batches: repo fields as in SPEC.md plus `owner{login __typename createdAt? (User/Organization createdAt)}`, `pushedAt`, `latestRelease{publishedAt}`, `licenseInfo`, and manifest blobs `object(expression:"HEAD:<path>"){...on Blob{text isTruncated}}` for: `package.json`, `pyproject.toml`, `server.json`, `plugin.json`, `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, `.codex-plugin/plugin.json`, `.cursor-plugin/plugin.json`, `SKILL.md`, `README.md` (first 20000 chars only for rule R6). SKILL.md is often nested: also list tree entries of `HEAD:` , `HEAD:skills`, `HEAD:.claude/skills`, `HEAD:.agents/skills` (name + type) and fetch `<dir>/<name>/SKILL.md` for up to 5 skills per repo.
Curation rules (write each rejection with a reason code; report counts per code):
- R1 `owner_unclear`: owner not resolvable, OR repo is a fork, OR owner account younger than 180 days at build date. "Pemilik jelas" = none of these.
- R2 `inactive`: both `pushedAt` and latest release older than 183 days at build date ("aktif 6 bulan").
- R3 `archived_or_disabled`.
- R4 `no_manifest`: none of the manifests above parses (JSON/TOML/frontmatter). Must be readable, not guessed from README.
- R5 `lifecycle_fetch`: package.json `scripts.preinstall|install|postinstall|prepare` contains a network fetch (curl, wget, http://, https://, iwr, Invoke-WebRequest, fetch(, node -e with http) or pyproject build hooks doing the same.
- R6 `pipe_to_shell`: README install code blocks, manifest commands or hook commands contain: `curl|wget ... | sh|bash|zsh|python|node`, `bash <(curl`, `iwr|irm ... | iex`, `Invoke-Expression`, `base64 -d|--decode ... | sh`, `eval $(`, or a command string that is base64/hex-obfuscated. Any match = reject (we do not tell people to paste scripts from outside URLs).
- R7 `disguised_install`: the repo's own documented install command (README/manifest) differs from what its manifest runs (e.g. `npx` package name not matching `package.json` name, or `server.json` package identifier that does not exist in the repo's manifest) — reject when detectable; otherwise pass.
- R8 `not_ai_tool`: none of type MCP / skill / plugin could be determined.
Type detection from manifests: MCP = `server.json` present, or registry source, or package.json/pyproject with an MCP SDK dependency (`@modelcontextprotocol/sdk`, `mcp`, `fastmcp`, `mcp-server-*`); skill = `SKILL.md` with frontmatter (`name`, `description`); plugin = any of the plugin.json / marketplace.json manifests. A repo may have several types.
Per-tool support: `tools` = set of {claude-code, claude-desktop, cursor, vscode, codex} for which this entry has a documented mechanism (see matrix in install_methods.md), derived from type + manifests (e.g. `.cursor-plugin/plugin.json` => cursor plugin; `.claude-plugin/marketplace.json` => claude-code plugin).

## 2. Data (`site/public/data/`)
- `catalog-ai.json`: `{generated_at, count, entries:[{slug, repo, name, owner, avatar, desc, stars, types:[mcp|skill|plugin], tools:[...], category, prerequisites:[node|python|uv|api_key|docker|none...], latest_activity_at, sources:[{kind:"registry"|"gh_topic", ref}], install_summary:{oneclick:bool, oneline:bool, snippet:bool, manual:bool}, access:{...}, trending}]}`.
- `ai/<slug>.json`: card + `manifests_found:[paths]`, `install:{ "<tool>": {type_key:{kind:"oneclick"|"oneline"|"snippet"|"manual"|"none", label, text|url, file_path_by_os?, note, prerequisites_plain, source_url}}}`, `access`, `readme_excerpt_removed:true` (no README shown).
- `stats-ai.json`: entries per type, per tool, % with oneclick/oneline/snippet/manual (best method per entry), rejections per reason code, sources counts.
Install text generation is deterministic from manifest fields only: npm package -> `npx -y <pkg>` (+args from server.json `packageArguments` if any); pypi -> `uvx <pkg>`; remotes -> url (streamable-http/sse; Claude Code `--transport http`). Required env vars (server.json `environmentVariables` isRequired) become placeholders `<ISI_DI_SINI>` and a plain-language prerequisite ("butuh API key: NAMA"). Cursor oneclick only for stdio `npx` configs (the only documented example); everything else Cursor = snippet. Config snippets always show the file path (per OS where documented; otherwise show the documented `~` form and say the OS path is not documented).

## 3. "Yang bisa diakses" box (every detail page, before any install button)
Fields: `files`, `terminal`, `network`, `api_keys`. Value set: a short Indonesian sentence from manifest evidence, else exactly `tidak diketahui`. Evidence rules: remotes present -> network "server jauh di <host>"; stdio npm/pypi -> "menjalankan program dari paket <name> di komputer Anda dengan hak akun Anda" (that is a fact about npx/uvx); `server.json environmentVariables` -> api_keys list (name, isRequired, isSecret); SKILL.md `allowed-tools` -> map Bash->terminal, Read/Write/Edit->file (if absent: `tidak diketahui`); plugin manifests with `hooks` or `mcpServers` -> "memasang hook / server MCP yang menjalankan perintah". Never infer from README. Never say safe/aman; add the fixed line "Ini daftar apa yang diminta manifest, bukan penilaian keamanan."

## 5. Real installs (5 entries) — plan fixed BEFORE running
Tools on this machine: check with `where claude`, `where code`, `where cursor`, `where codex`. Pick 5 entries with NO API key, from the official registry source, using the exact method the site shows for that tool. Safety: back up every config file touched (copy to scratchpad first), prefer project/workspace scope inside a scratch directory, never write into the user-scope config of the Claude Code session in use; revert afterwards (remove entries, restore backups). Success = the tool's own listing shows it (`claude mcp list`, `codex mcp list`, `code --list-extensions`/mcp.json parse, etc.) and, for MCP stdio, the tool reports the server connected or lists tools when feasible. Report per entry: tool, method, command run, result, revert done. Anything that cannot be tested here is reported "tidak diuji", not "berhasil".
